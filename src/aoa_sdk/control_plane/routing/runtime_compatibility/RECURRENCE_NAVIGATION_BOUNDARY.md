# Recurrence Navigation Boundary

Recurrence is the law. Return is the concrete re-entry seam.

The routing control plane may compress the next valid source-owned surface for
re-entry. It must not decide whether return is justified, reinterpret a
checkpoint, grant runtime authority, or turn a navigation hint into memory or
proof.

The stable public surface remains
`generated/return_navigation_hints.min.json`. Its owner metadata follows the
canonical routing producer; source-authority targets continue to point to the
repositories that own their meaning.

Before G5, an `aoa-sdk`-identified bundle is candidate-only and may enter only
an isolated or explicitly authorized canary route. After G5, the SDK may own
the routing producer while runtime policy, activation, execution, evaluation,
retention, and closeout authority remain external.

Runtime and agent consumers must keep return navigation:

- deterministic and typed;
- bounded to explicit inspect, expand, recall, or handoff actions;
- owner-qualified;
- free of hidden fallback activation;
- weaker than the source surface it references.

The runtime mirror is not authority. It must remain bound to an exact source
ref, content hashes, artifact-subject digest, durable trust record, and
consumer-specific admission verdict.
